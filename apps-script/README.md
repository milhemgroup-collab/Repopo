# Apps Script Routine Framework

A generic, config-driven Apps Script project for running scheduled or on-demand
routines against Google services (Gmail, Drive, Sheets, Calendar) — and beyond.
The REPS sheet-appender is the first routine; new routines are added by
appending one entry to the registry, not by writing new framework code.

## Why this exists

The previous `reps_sheet_appender.gs` was a single 520-line file that did
everything inline. When the parser failed on three of four real-world email
formats, the code was hard to isolate, hard to test, and tied to a single
workflow. This framework splits the surface area into small, named layers so
that:

- adding a new routine = adding ~30 lines of config
- a parser bug is fixed in one file (`03_Parsers.gs`) and trivially unit-tested
- a single routine failing inside the hourly trigger cannot break the others
- everything is reachable from Claude Code via a single authenticated Web App

## Layout

| File | Role |
|------|------|
| `appsscript.json` | Manifest, OAuth scopes, Web App config |
| `00_Code.gs` | Entry points: `setup`, `runOnce`, `runRoutine`, `doGet`, `doPost` |
| `01_Routines.gs` | Routine registry + schema validator + `prop:` resolver |
| `02_Sources.gs` | `Sources.gmail`, `drive_folder`, `sheet_range`, `calendar`, `url_fetch` |
| `03_Parsers.gs` | `Parsers.reps_rows` (handles all 4 known formats), `json`, `csv`, `passthrough` |
| `04_Sinks.gs` | `Sinks.sheet_append`, `gmail_send`, `drive_write`, `calendar_create`, `noop` |
| `05_Dedupe.gs` | `Dedupe.sheet_key`, `memory_key`, plus `none` (default) |
| `06_PostActions.gs` | Per-item labels/replies/archive after success or failure |
| `07_Reliability.gs` | `safeRun`, `withRetry`, `log_`, `heartbeat`, `_log` sheet |
| `08_REPS_Routine.gs` | The REPS routine config (uses `prop:` for sensitive values) |
| `09_Helpers.gs` | `unlabelFailed`, `listRoutines`, `getStatus`, `resetWebAppToken` |
| `10_Tests.gs` | Smoke tests including all 4 REPS body formats |

## How a routine is shaped

```js
{
  id: 'reps_appender',
  enabled: true,
  source: { type: 'gmail', query: 'prop:REPS_GMAIL_QUERY', excludeLabels: [...], maxThreads: 25 },
  parse:  { type: 'reps_rows', expectedCountRegex: /Rows?\s*\(?\s*(\d+)\s*\)?/i },
  dedupe: { type: 'sheet_key', sheetId: 'prop:REPS_SHEET_ID', sheetName: 'prop:REPS_SHEET_TAB', composite: [0, 1, 2] },
  sink:   { type: 'sheet_append', sheetId: 'prop:REPS_SHEET_ID', sheetName: 'prop:REPS_SHEET_TAB',
            formulaColumns: { '4': 'prop:REPS_HOURS_FORMULA' } },
  postActions: {
    onSuccess: { addLabels: ['REPS/Processed'], removeLabels: ['REPS/AppendFailed'] },
    onFailure: { addLabels: ['REPS/AppendFailed'] }
  }
}
```

Anything quoted as `prop:KEY` is resolved at runtime from ScriptProperties.
This keeps secrets, sheet IDs, and per-environment quirks out of source.

## Adding a new routine

1. Add a `register<Name>Routine_()` function in a new `08_*_Routine.gs` file.
2. Append it to the registry in `01_Routines.gs::getRoutineRegistry_()`.
3. Push (e.g. `clasp push`), then `setup()` again — it re-validates configs.
4. The next hourly trigger picks it up. Or hit `?action=run&id=<routine>` on the Web App.

## Web App API

All endpoints require `?token=<WEBAPP_TOKEN>` (or `{token: ...}` in POST body).

| URL | Action |
|-----|--------|
| `?action=status&token=...` | Version + list of routines |
| `?action=run&id=<id>&token=...` | Run one routine, return report |
| `?action=runAll&token=...` | Run every enabled routine |
| `?action=unlabelFailed&label=REPS/AppendFailed&token=...` | Strip a label from all threads |

Example from Claude Code:

```bash
curl -sX POST "$WEBAPP_URL" \
  -H 'Content-Type: application/json' \
  -d "{\"token\":\"$TOKEN\",\"action\":\"run\",\"id\":\"reps_appender\"}"
```

## Required ScriptProperties

| Key | Value |
|-----|-------|
| `WEBAPP_TOKEN` | Auto-generated by `setup()` (rotate with `resetWebAppToken()`) |
| `REPORT_EMAIL` | Where run reports & heartbeats go (defaults to deploying user) |
| `LOG_SHEET_ID` | Spreadsheet to host the `_log` sheet (falls back to the first routine's sink) |
| `REPS_SHEET_ID` | The REPS spreadsheet to append into |
| `REPS_SHEET_TAB` | Tab name within that spreadsheet |
| `REPS_GMAIL_QUERY` | Gmail search, e.g. `from:reps-hour-logger@... subject:"BACKFILL"` |
| `REPS_HOURS_FORMULA` | D-column formula template; `{row}` is replaced per row |
| `HEARTBEAT_MAX_HOURS` | Optional; defaults to 6h |
